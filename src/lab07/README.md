# Отчет по лабораторной работе №7

## Алгоритмы поиска

- `linear_search(nums, x)` — линейный поиск первого вхождения элемента;
- `binary_search(sorted_nums, x)` — бинарный поиск в отсортированном списке;
- `two_sum_brute(nums, target)` — поиск пары вложенными циклами;
- `two_sum_fast(nums, target)` — поиск пары за один проход со словарём.

Сложность:

| Алгоритм            | Сложность |
| --------------------------- | -----------------: |
| Линейный поиск |           `O(n)` |
| Бинарный поиск |       `O(log n)` |
| `two_sum_brute`           |         `O(n²)` |
| `two_sum_fast`            |           `O(n)` |

Бинарный поиск работает только с предварительно отсортированным списком.

## Алгоритмы сортировки

- `bubble_sort(nums)` — сортировка пузырьком с ранним выходом;
- `insertion_sort(nums)` — сортировка вставками;
- `selection_sort(nums)` — сортировка выбором;
- `merge_sort(nums)` — нерекурсивная сортировка слиянием;
- `counting_sort(nums, lo, hi)` — сортировка подсчётом для заданного диапазона.

| Алгоритм                            | Сложность |
| ------------------------------------------- | -----------------: |
| Пузырьковая сортировка |         `O(n²)` |
| Сортировка вставками     |         `O(n²)` |
| Сортировка выбором         |         `O(n²)` |
| Сортировка слиянием       |     `O(n log n)` |
| Сортировка подсчётом     |       `O(n + k)` |

### Сортировки

Квадратичные сортировки для `n = 100000` ограничены отметкой `> 60.0`,
поскольку их выполнение занимает слишком много времени.

### Сортировка подсчётом

Для миллиона чисел из диапазона `[0, 100]` получены следующие результаты:

| Размер `n` | Реализация |  Время |
| -----------------: | -------------------- | ----------: |
|          1 000 000 | `sorted`           | 0.124700 с |
|          1 000 000 | `counting_sort`    | 0.063189 с |

Сортировка подсчётом примерно в два раза быстрее `sorted` в этом случае,
потому что размер диапазона значений значительно меньше количества элементов.

### Поиск

Замер выполнен для списка из 100 000 элементов и 10 000 запросов.

| Реализация                   |   Время |
| -------------------------------------- | -----------: |
| Линейный поиск            | 25.951250 с |
| Сортировка списка      |  0.022157 с |
| 10 000 бинарных поисков |  0.025957 с |

Бинарный поиск требует предварительной сортировки. При одном запросе
линейный поиск выгоднее, но при большом числе запросов стоимость сортировки
быстро окупается: после неё каждый запрос выполняется за `O(log n)`.

### Two Sum

| Размер `n` | `two_sum_brute` | `two_sum_fast` |
| -----------------: | ----------------: | ---------------: |
|              1 000 |       0.016020 с |      0.000071 с |
|             10 000 |       0.021130 с |      0.000276 с |

Решение со словарём заметно быстрее перебора пар и масштабируется линейно.

## Вывод

При увеличении размера списка с 1 000 до 10 000 элементов пузырьковая сортировка замедлилась примерно в 121 раз: это соответствует квадратичной сложности `O(n²)`. 

Для `sorted` рост составил около 39 раз в данном запуске, 

а для `merge_sort` — около 14 раз; 

на практике результат зависит от реализации, процессора и конкретных данных, но асимптотика `O(n log n)` растёт значительно медленнее квадратичной.

Бинарный поиск сам по себе очень быстрый, но применим только к отсортированному списку. Поэтому для небольшого числа запросов стоимость сортировки может быть неоправданной, а при тысячах запросов она окупается. 

Проверка `check.py` подтвердила корректность всех пяти сортировок, двух алгоритмов поиска и двух решений `Two Sum`: расхождений на 100 случайных тестах для каждого набора не
обнаружено.
